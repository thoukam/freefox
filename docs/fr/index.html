Récupérez chaque rosbag de vos robots, sans en perdre un.

FreeFox surveille votre dossier d'enregistrement et envoie les bags terminés vers Google Drive, un NAS via rsync/SSH ou tout bucket compatible S3. Les uploads reprennent après un crash, chaque fichier est vérifié avec BLAKE3, et un dashboard en direct montre ce qui se passe.

pip install "freefox[s3]"
Commencer ★ GitHub PyPI

Pourquoi FreeFox ?

Un robot de terrain enregistre des gigaoctets de rosbags à chaque mission, souvent sur un Wi-Fi ou une 4G instable. Copiés à la main, des bags se perdent, se dupliquent ou se corrompent, et on ne s'en rend compte qu'au moment d'exploiter les données.

⏳

Uniquement des bags complets

Un fichier n'entre en file que lorsqu'il ne grossit plus et qu'aucun processus ne le tient ouvert.

🗃️

Rien ne se perd

Chaque transfert est gardé dans une file SQLite locale, malgré les crashs et redémarrages.

⏯️

Reprendre, pas recommencer

Un upload de 20 Go interrompu repart là où il s'est arrêté, sur chaque backend.

🔏

Preuve d'intégrité

Une empreinte BLAKE3 est stockée côté distant et vérifiée. Un même contenu n'est jamais envoyé deux fois.

Fonctionnement

FreeFox tourne à côté de votre stack ROS 2. Il ne touche pas à ROS lui-même : il surveille un dossier.

flowchart LR
    bags[("📁 dossier des bags<br/>ros2 bag record")] --> W["👁️ Watcher<br/>attend que le bag<br/>soit complet"]
    W --> Q[("🗃️ File SQLite<br/>état durable")]
    Q --> P["⚙️ Workers<br/>BLAKE3 · retries<br/>reprise"]
    P --> GD["☁️ Google Drive"]
    P --> RS["🗄️ NAS / serveur"]
    P --> S3["🪣 S3 / MinIO"]
    D["📊 Dashboard"] -.-> Q

    classDef core fill:#FF6B00,stroke:#E63200,color:#ffffff
    class W,P core
  1. Surveiller. Les nouveaux fichiers .mcap et .db3 sont détectés ; FreeFox attend qu'ils ne grossissent plus.
  2. Mettre en file. Le transfert est enregistré avec un instantané de sa destination : il survit aux redémarrages.
  3. Envoyer. Les workers calculent le BLAKE3, ignorent ce qui existe déjà, envoient avec reprise et réessaient avec backoff.
  4. Ne jamais écraser. Un fichier différent déjà présent au même chemin devient un conflit, qu'un opérateur tranchera.

Fonctionnalités

Tout ce qu'une équipe robotique attend pour collecter ses données terrain, avec le stockage qu'elle a déjà.

☁️

Trois backends

Google Drive (OAuth2 ou Shared Drive), rsync vers un disque, un NAS ou un serveur SSH, et AWS S3 ou MinIO.

🔁

Retries intelligents

Backoff exponentiel, délais dédiés aux erreurs de quota et réseau, échecs remis en file au démarrage.

📊

Dashboard en direct

Progression par bag, débit en MiB/s et Mbps, ETA, retries, erreurs et fichiers surveillés.

🗂️

Arborescence propre

Les fichiers arrivent sous robot_id/AAAA-MM-JJ/, prêts pour toute une flotte.

🔐

Sécurisé par défaut

Clés S3 refusées dans le YAML, secrets masqués dans les logs, unité systemd durcie.

🐳

Tourne partout

pip, systemd ou Docker. Image multi-architecture amd64 et arm64 (Jetson, Raspberry Pi).

Le dashboard local (aperçu flouté).

Installation

Choisissez la méthode adaptée à votre robot. Toutes utilisent le même fichier de configuration.

pip

Le plus rapide pour essayer, ou sur un robot qui a déjà Python.

pip install "freefox[s3]"
freefox --config config.yaml
freefox-dashboard --config config.yaml --host 0.0.0.0

Docker

Le service et le dashboard dans deux conteneurs, amd64 et arm64.

git clone https://github.com/thoukam/freefox && cd freefox
cp .env.example .env
cp config/config.docker.example.yaml config/config.docker.yaml
docker compose up -d

systemd

Démarre au boot, redémarre en cas d'erreur, unité durcie.

git clone https://github.com/thoukam/freefox && cd freefox
sudo ./install.sh && sudo nano /etc/freefox/config.yaml
sudo systemctl enable --now freefox

Configuration minimale

robot_id: robot-01            # par défaut : le hostname
watch:
  directory: /home/ros/bags
storage:
  backend: rsync              # gdrive | rsync | s3
rsync:
  destination: user@nas:/data/freefox

Toutes les options sont documentées dans config.example.yaml.
