# Installation

This guide covers a local install for testing, then a systemd service on a robot or any Linux
machine. For Docker, see [docker-deployment.md](docker-deployment.md).

## Requirements

- Linux
- Python 3.10 or newer, with `pip`
- A storage backend:
  - Google Drive: see [google-drive-setup.md](google-drive-setup.md)
  - rsync: a local or SSH destination (`rsync` and `openssh-client` installed)
  - S3 / MinIO: an existing bucket, see [s3-storage.md](s3-storage.md)

Optional: `sqlite3` to inspect the upload queue database.

## Local development install

```bash
git clone https://github.com/thoukam/freefox
cd freefox
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"        # add ,s3 for the S3 backend: ".[dev,s3]"
```

`-e` means *editable*: the installed `freefox` command runs the code in the repository directly.
boto3 stays optional and is only imported when `storage.backend: s3` is selected.

Check it:

```bash
.venv/bin/freefox --help
.venv/bin/python -m pytest
.venv/bin/python scripts/local_smoke.py   # end-to-end run, no cloud account needed
```

> **ROS 2 sourced in your shell?** ROS adds its own pytest plugins to `PYTHONPATH`. If test
> collection fails, run
> `env -u PYTHONPATH PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/python -m pytest -p pytest_timeout`.

Files generated by pip (`freefox.egg-info/`, `.venv/`) are ignored by git. Do not edit them by hand.

## Local configuration

```bash
cp config/config.example.yaml config/local.gdrive.yaml
```

Minimal Google Drive example:

```yaml
robot_id: pc-test

watch:
  directory: /tmp/freefox-bags
  stable_seconds: 2.0

upload:
  workers: 1
  chunk_size: 8388608
  verify_blake3: true
  deduplicate_by_hash: true

drive:
  credentials_file: ./secrets/freefox-oauth-client.json
  target_folder_id: "GOOGLE_DRIVE_FOLDER_ID"

queue_db: /var/lib/freefox/queue.db
```

Every option is commented in [`config/config.example.yaml`](../../config/config.example.yaml).
`config/local*.yaml` files are ignored by git.

## Google Drive check

```bash
FREEFOX_TOKEN_PATH=./secrets/freefox-token.json \
.venv/bin/python scripts/gdrive_smoke.py --config config/local.gdrive.yaml
```

On the first OAuth2 run, Google opens a browser for consent. The token is then written to
`FREEFOX_TOKEN_PATH`.

## Testing with real rosbags

```bash
mkdir -p /tmp/freefox-bags
FREEFOX_TOKEN_PATH=./secrets/freefox-token.json \
.venv/bin/freefox --config config/local.gdrive.yaml
```

In another terminal:

```bash
cp /path/to/your/bag.mcap /tmp/freefox-bags/
```

FreeFox waits until the file size has been stable for `watch.stable_seconds`, queues it, then
uploads it to `<robot_id>/<YYYY-MM-DD>/<filename>`, for example `pc-test/2026-06-05/bag.mcap`.

Inspect the queue:

```bash
.venv/bin/python scripts/queue_status.py /var/lib/freefox/queue.db
# or
sqlite3 -header -column /var/lib/freefox/queue.db \
  "SELECT id, local_path, remote_path, status, retries, error FROM queue;"
```

## Installing as a systemd service

```bash
sudo ./install.sh
sudo nano /etc/freefox/config.yaml
sudo systemctl enable --now freefox
journalctl -u freefox -f
```

`install.sh`:

- installs the Python package (with the S3 extra),
- creates `/etc/freefox` and `/var/lib/freefox`,
- copies `config/config.example.yaml` to `/etc/freefox/config.yaml` if it does not exist,
- installs `systemd/freefox.service` for the user who runs `sudo`. You can override this with
  `SERVICE_USER=... SERVICE_GROUP=...`.

The unit is hardened (`ProtectSystem=strict`, `ProtectHome=read-only`, `PrivateTmp=true`). If you
set `delete_after_upload: true`, add the bags folder to `ReadWritePaths` with
`sudo systemctl edit freefox`.

Under systemd, do not keep the queue database in `/tmp`. Because of `PrivateTmp=true`, the service
sees a private `/tmp` that your tools cannot see. Use `/var/lib/freefox/queue.db`.

## Restarts and upload resume

Each transfer's state lives in SQLite: status, retries, progress, BLAKE3 digest, Google Drive
session URI and S3 parts already sent.

On restart, entries left in `uploading` go back to `queued`:

- **Google Drive**: the worker reuses the saved session URI, asks Google which byte range it already
  holds, and continues from there. An expired session is cleared and recreated.
- **S3**: parts that are already confirmed are not sent again.
- **rsync**: `--partial --inplace` resumes the partially transferred file.

The database must persist across restarts and stay protected, because session URIs are sensitive.

## Local web dashboard

```bash
.venv/bin/python scripts/dashboard.py --config config/local.gdrive.yaml --host 127.0.0.1 --port 8765
```

Open `http://127.0.0.1:8765`. To reach it from another PC on the network, use `--host 0.0.0.0` and
open `http://ROBOT_IP:8765` (`hostname -I` shows the IP).

The dashboard shows status, progress, duration, throughput, ETA, retries, errors, files in the
watched folder and current incidents. It reads the same SQLite database as the service.

> The dashboard has no authentication yet. Expose it only on a trusted network, never on the
> Internet.

## Environment variables

| Variable | Purpose |
|---|---|
| `FREEFOX_ROBOT_ID` | Overrides `robot_id` from the YAML |
| `FREEFOX_CREDENTIALS` | Overrides `drive.credentials_file` |
| `FREEFOX_TOKEN_PATH` | OAuth2 token cache (default: `/var/lib/freefox/token.json`) |
| `AWS_*` | Standard credential chain for S3, see [s3-storage.md](s3-storage.md) |
