Get every rosbag off your robots, reliably.

FreeFox watches your recording folder and ships finished bags to Google Drive, a NAS over rsync/SSH or any S3-compatible bucket. Uploads resume after a crash, every file is verified with BLAKE3, and a live dashboard shows what is happening.

pip install "freefox[s3]"
Get started ★ GitHub PyPI

Why FreeFox?

Field robots record gigabytes of rosbags per run, often on flaky Wi-Fi or 4G. Copied by hand, bags get lost, duplicated or corrupted, and nobody notices until the data is needed.

⏳

Complete bags only

A file is queued only once it has stopped growing and no process holds it open.

🗃️

Nothing gets lost

Every transfer lives in a local SQLite queue that survives crashes and reboots.

⏯️

Resume, don't restart

An interrupted 20 GB upload continues where it stopped, on every backend.

🔏

Proof of integrity

A BLAKE3 fingerprint is stored remotely and checked. Identical content is never sent twice.

How it works

FreeFox runs next to your ROS 2 stack. It does not touch ROS itself: it watches a folder.

flowchart LR
    bags[("📁 bags folder<br/>ros2 bag record")] --> W["👁️ Watcher<br/>waits until the<br/>bag is complete"]
    W --> Q[("🗃️ SQLite queue<br/>durable state")]
    Q --> P["⚙️ Workers<br/>BLAKE3 · retries<br/>resume"]
    P --> GD["☁️ Google Drive"]
    P --> RS["🗄️ NAS / server"]
    P --> S3["🪣 S3 / MinIO"]
    D["📊 Dashboard"] -.-> Q

    classDef core fill:#FF6B00,stroke:#E63200,color:#ffffff
    class W,P core
  1. Watch. New .mcap and .db3 files are detected; FreeFox waits until they stop growing.
  2. Queue. The transfer is recorded with a snapshot of its destination, so it survives reboots.
  3. Upload. Workers compute BLAKE3, skip what already exists, upload with resume and retry with backoff.
  4. Never overwrite. A different file already at the same path becomes a conflict for an operator to decide.

Features

Everything a robotics team needs to collect field data, with the storage it already has.

☁️

Three backends

Google Drive (OAuth2 or Shared Drive), rsync to a disk, NAS or SSH server, and AWS S3 or MinIO.

🔁

Smart retries

Exponential backoff, dedicated delays for quota and network errors, failed items requeued on start.

📊

Live dashboard

Per-bag progress, MiB/s and Mbps throughput, ETA, retries, errors and watched files.

🗂️

Tidy layout

Files land under robot_id/YYYY-MM-DD/, ready for a whole fleet.

🔐

Secure by default

S3 keys are refused in YAML, secrets are redacted from logs, the systemd unit is hardened.

🐳

Runs anywhere

pip, systemd or Docker. Multi-arch image for amd64 and arm64 (Jetson, Raspberry Pi).

Install

Pick the way that fits your robot. Every option uses the same configuration file.

pip

Quickest way to try it, or to run it on a robot that already has Python.

pip install "freefox[s3]"
freefox --config config.yaml
freefox-dashboard --config config.yaml --host 0.0.0.0

Docker

Service and dashboard in two containers, amd64 and arm64.

git clone https://github.com/thoukam/freefox && cd freefox
cp .env.example .env
cp config/config.docker.example.yaml config/config.docker.yaml
docker compose up -d

systemd

Starts at boot, restarts on failure, hardened unit.

git clone https://github.com/thoukam/freefox && cd freefox
sudo ./install.sh && sudo nano /etc/freefox/config.yaml
sudo systemctl enable --now freefox

Minimal configuration

robot_id: robot-01            # defaults to the hostname
watch:
  directory: /home/ros/bags
storage:
  backend: rsync              # gdrive | rsync | s3
rsync:
  destination: user@nas:/data/freefox

Every option is documented in config.example.yaml.
